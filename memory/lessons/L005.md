# L005 Preflight Gate Before Demo Animation Build

## Tags

problem-understanding-error, memory-retrieval-error, tooling-missing-error, self-check-error, hyperframes, remotion

## Error Type

knowledge-expression-error / technical-implementation-error / visual-layout-error / timing-sync-error

## Error Manifestation

The animation process starts too quickly: the task meaning is not verified, the answer or reasoning path is wrong, memory files are skipped, the build falls back to plain HTML/SVG/Canvas instead of HyperFrames or Remotion, tooling is missing, and self-check does not block obvious errors.

## Correct Approach

Run a hard preflight gate before implementation:

1. Read `memory/rules.json`.
2. Search `memory/issue_log.md` and `memory/lessons_index.md` by task tags.
3. Verify problem meaning, givens, target, constraints, forbidden assumptions, solution path, and final answer.
4. Select HyperFrames or Remotion as the primary production route.
5. Check or install required tooling.
6. Create the scene table, timeline table, element state table, key action table, and self-check checklist.
7. Fix objective logic, layout, timing, asset, or export errors before presenting work as ready.

## Reusable Rule

Do not implement demo animation until memory retrieval, problem/answer verification, HyperFrames-or-Remotion selection, tooling readiness, planning tables, and self-check gate all pass.

## Applicable Scenarios

- Math, science, route, puzzle, proof, and diagram animations.
- Course animations requiring correct answer logic.
- Any exportable demo animation where the final implementation must be HyperFrames or Remotion.
- Projects where repeated user feedback shows weak self-check or skipped memory retrieval.
